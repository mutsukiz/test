# 3D四足・9-IMU状態推定(胴体姿勢+関節たわみ同時推定)

胴体1+大腿4+下腿4の計9個のIMUと12個の関節エンコーダを
Error-State EKFで融合し、**胴体姿勢**と**全12関節のたわみ
δ = リンク角 − モータ角(低剛性・バックラッシュによるズレ)**を
同時推定する。平面プロトタイプ(`multi_imu_leg/`)の3D拡張版。

## ファイル構成

| ファイル | 内容 | 検証状態 |
|---|---|---|
| `quad_geom.py` | 共有ジオメトリ(股オフセット、関節軸、リンク長、IMU位置、ToF仕様) | ✔ |
| `estimator3d.py` | 9-IMU+足裏ToF ESKF本体(誤差状態87次元) | ✔ 検証済み |
| `sim3d_numpy.py` | 運動学ベース合成データ生成(IMU+ToF、推定器検証用) | ✔ 検証済み |
| `sim3d_pybullet.py` | PyBullet動力学バックエンド(SEA関節+仮想ハーネス+ToFレイキャスト) | ⚠ 未実行(要 `pip install pybullet`) |
| `check_model.py` | 観測モデル整合性チェック(IMU+ToF、座標系ミス検出用) | ✔ |
| `demo3d.py` | 実行・評価・可視化(ToFあり/なし比較を含む) | ✔ |

## 実行

```bash
python check_model.py          # まず整合性チェック(必須)
python demo3d.py               # numpyバックエンド
python demo3d.py --pybullet    # PyBulletバックエンド(手元で)
```

**PyBulletを使う前に必ず `python check_model.py --pybullet` を実行**
してください。ジャイロ残差 < 0.05 rad/s、加速度残差 < 0.3 m/s² なら
URDFのリンク座標系と推定器の運動学モデルが整合しています。
このチェックは実機データ(モーションキャプチャ等の真値付き)にも
そのまま流用できます。

## 状態量と誤差状態(基本54次元、ToF拡張時87次元)

```
q_WB (4)  : 胴体姿勢クォータニオン       誤差 dθ ∈ R³(右乗算)
δ    (12) : 関節たわみ [FL,FR,RL,RR]×[外転,股P,膝]
δ̇   (12) : たわみ速度
b_g  (9,3): 全IMUのジャイロバイアス
```
ToF拡張時はさらに `p, v (3,3)` (胴体位置・速度, INS) と
`b_a (9,3)` (加速度計バイアス) を追加(詳細は下記セクション)。

## アルゴリズム

**予測(500 Hz)**: 胴体ジャイロで姿勢積分。δはδ̇で積分、
δ̇・バイアスはランダムウォーク。

**更新(~167 Hz, まとめて1回、51次元観測)**:

1. **リンクジャイロ観測(8×3)**: 運動学チェーンによる角速度伝播
   `ω_thigh = R₂ᵀR₁ᵀω_B + R₂ᵀa₁q̇₁ + a₂q̇₂ + b`(q̇ = q̇_m + δ̇)。
   δ̇とリンクバイアスを拘束。
2. **リンク加速度計観測(8×3, 本手法の核)**: 胴体加速度計から胴体点の
   並進加速度を復元し、角速度・角加速度で運動学チェーンを世界座標で
   伝播して各IMU位置の比力を予測(**動的加速度補償**)。残差は
   リンク間相対角=δに鋭敏で、δの絶対値を強く拘束する。
   ※ 素朴な「加速度計=傾斜計」はスイング脚の動的加速度(>20 m/s²)で
   破綻することを2Dで実証済み。
3. **胴体傾斜(3)**: 重力方向の緩い更新。roll/pitchのドリフト抑制。
   **yawは磁気/視覚なしでは原理的に不可観測**でゆっくりドリフトする
   (脚オドメトリや外部センサ追加で解消、下記ロードマップ)。

ヤコビアンは全て数値微分(boxplus摂動)で導出ミスを排除。
脚ごとのブロック疎構造を利用して高速化(10 s / 500 Hzデータで約35 s)。
角加速度はゼロ位相平滑ジャイロの微分(オンラインは固定ラグFIRで代替)。

## 代表結果(numpyバックエンド, 500 Hz, 10 s, トロット1.5 Hz)

| 量 | 推定 | 比較 |
|---|---|---|
| roll / pitch RMSE | 0.54° / 1.32° | ー |
| 股ピッチδ RMSE | 0.08–0.11° | 剛体仮定 0.91°(**8–11倍改善**) |
| 膝δ RMSE | 0.11–0.17° | 剛体仮定 0.55°(**3–5倍改善**) |
| 股外転δ RMSE | ~0.08–0.11° | 剛体仮定 0.07°(真値が推定床以下で改善せず) |
| ジャイロバイアス | RMS誤差 0.004 rad/s | 真値 ±0.03 rad/s |

股外転は本シミュレーション条件では真のたわみが0.07°しかなく、
推定ノイズ床(~0.1°)を下回るため改善しない。実機で外転負荷が
大きい場合(横歩き等)は改善が見込める。

## 足裏ToF距離センサの追加(位置・姿勢の強化)

各下腿の足先にToF距離センサ(VL53L1X級、レンジ 1.5〜35 cm、σ=6 mm)を
追加し、地面までの距離を観測に統合できる。

### 動機と効果

9-IMU構成だけでは胴体の**絶対位置**(特に高さ)は加速度の二重積分
(INS)でしか得られず、バイアス誤差が二次関数的に蓄積して短時間で
数十cm〜m単位でドリフトする。姿勢もこの位置誤差と結合してゆっくり
汚染される。足裏ToFは「地面までの距離」という絶対量を直接観測する
ため、このドリフトを止められる。

### 状態拡張(54→87次元)

```
+ p  (3) : 胴体位置(INS)         誤差 dp
+ v  (3) : 胴体速度(INS)         誤差 dv
+ ba (9,3): 全IMUの加速度計バイアス  誤差 db_a
```
胴体加速度計をIMU力学(INS)として積分し、位置・速度を推定する。
加速度計バイアスを状態に加えたのは、バイアス既知のIMUは現実には
存在せず、ToFで補正できる絶対量がないとバイアスと重力オフセットが
区別できず発散するため。

### 観測モデル

```
h_tof(leg) = -p_foot_z / (R_WS @ [0,0,-1])_z
```
足先位置 `p_foot` は胴体位置+運動学チェーン(股オフセット→大腿→
下腿→ToF取り付けオフセット)。地面を `z=0` の平面と仮定(不整地は
将来課題、下記ロードマップ参照)。レイの傾き `u_z` が浅い
(`> -TOF_MAX_TILT`、足が真下を向いていない=遊脚中など)場合は
その足のToFを無効化する。3σの外れ値ゲートも実装(地面の凹凸や
反射不良によるスパイク対策)。

### 代表結果(加速度計バイアス ±0.2 m/s² を含む厳しい条件)

| 量 | ToFなし | ToFあり |
|---|---|---|
| roll / pitch RMSE | 0.71° / 0.69° | **0.15° / 0.16°**(4〜5倍改善) |
| yaw RMSE | 8.98° | **1.02°**(9倍改善、脚の相対幾何拘束による間接効果) |
| 胴体高さ RMSE | 668 mm(INSドリフト) | **0.9 mm** |

たわみδ推定への直接効果は小さい(ToFはδを直接観測しないため)。
ToFは主に胴体の絶対位置・姿勢ドリフトの解消に効く。

**トレードオフの注意**: 加速度計バイアスを状態(27次元追加)として
持たせたことで、バイアスが実際には無い/小さい条件でもδ推定の
基礎精度がわずかに悪化する(例: 股ピッチδのRMSE 0.08〜0.11°→
0.08〜0.30°、剛体仮定比で x8〜11倍→x3〜12倍)。IMUのバイアス安定度が
十分高く(高品質MEMS)、実測でバイアスがほぼ無視できるなら
`acc_bias_walk`を小さくする、または加速度計バイアス状態を
外して単純化する方が、たわみ推定の精度は上がる。何を状態に含めるかは
実機のセンサ仕様に応じたトレードオフ。

### PyBulletバックエンドでの実装

`sim3d_pybullet.py` では `p.rayTestBatch` で実地形にレイキャストする
ため、平面仮定より現実的(段差・傾斜面でも動作)。実機でも同様に
「地面が平面」という仮定は不整地で崩れる点に注意(ロードマップ参照)。

### チューニングの勘所

- `tof_sigma`: センサ仕様のσ(VL53L1Xで数mm)をそのまま使ってよい
- `TOF_MAX_TILT`(quad_geom.py): 遊脚中の無効なレイを弾く角度しきい値。
  緩すぎると地面以外(自機の脚など)を測る誤検出が増える
- 3σゲートの閾値は共分散Pの収束前(起動直後)は緩め(ゲートで
  正しい観測まで弾いてしまう)。起動後数秒はゲートを無効化するか
  緩和するのが実用上おすすめ
- `accel_noise` / `acc_bias_walk`: IMUデータシートのVRW・バイアス
  安定度から設定。ToFがあってもこれらが大きすぎるとv, pの共分散が
  膨張し続け、収束が遅くなる


- **SEAモデル**: 各関節にトルク制御で τ = k(q_cmd−q) + c(q̇_cmd−q̇) を
  印加。q_cmd=モータ角(エンコーダ)、q=リンク角、δ=q−q_cmd が
  物理シミュレーションから自然に生じる。
- **仮想ハーネス**: 歩行制御器なしで転倒を防ぐ試験リグ(柔らかい
  ばね-ダンパ外力)。鉛直は弱くして脚に荷重を残す。制御器導入後は
  `harness=False`。
- 剛性 k=[80,60,40] Nm/rad は低剛性想定。発振する場合はダンピングc増
  またはsim刻み減。

## 実機(自作四足)への移行チェックリスト

1. `quad_geom.py` を実機の寸法・関節軸・IMU取り付け位置に合わせる
2. IMU取り付け姿勢のキャリブレーション(静置で重力方向、既知単軸
   動作でジャイロ軸を同定)。取り付け回転行列をモデルに挿入
3. IMU間の時刻同期(共通トリガ or タイムスタンプ補間)。500 Hz推奨
4. 静置数秒でジャイロバイアス初期化(推定の収束が大幅に速くなる)
5. `check_model.py` 相当の整合性チェックをロギングデータで実施
6. `link_acc_sigma` を実測残差の統計に合わせて調整
7. 加速度計バイアスの状態追加(長時間運用時)

## ロードマップ(残課題)

- ~~浮遊ベース位置・速度の追加~~ → ToF拡張で実装済み(平面地面前提)
- **不整地対応**: 現状は地面 `z=0` の平面仮定。傾斜・段差では
  ToF観測モデルに地形マップ(高さマップ or 局所平面フィッティング)
  を組み込む必要がある。あるいは接触足のゼロ速度更新(脚オドメトリ)
  に切り替え、ToFは接地判定・スリップ検出の補助に回す設計も有力
- 接触足のゼロ速度更新(脚オドメトリ)を追加すると、遊脚中心の
  ToFと相補的になりMIPO/DogLegs構成によりいっそう近づく
- 解析ヤコビアン化 or JAX化でリアルタイム性能向上
  (現状87次元状態で約束10 s分の推定に約70〜90 s、リアルタイムの
  約7〜9倍。update_everyやtof_everyの間引き、脚ブロックごとの
  並列化で改善余地あり)
- たわみ統計の監視による剛性低下・ガタ増大の異常検知モジュール
- 不変EKF(InEKF)化による初期値ロバスト性向上
